# Ход работы

## ЛР 1. Старт проекта на React и TypeScript

Создан проект `frontend` на Vite (шаблон react-ts). Стартовый экран заменён на экран приложения «Учебный менеджер»: название, описание и заглушка списка заданий. Проект опубликован в Git-репозитории.

### Как проверить

1. `cd frontend`, затем `npm ci`.
2. `npm run dev` и открыть адрес из терминала: виден экран «Учебный менеджер», счётчика и логотипов Vite нет.
3. Сузить окно или включить мобильный режим (320–375 px): горизонтальной прокрутки нет.
4. `npm run build`: проверка типов и сборка проходят без ошибок.
5. `npm run preview` и открыть адрес: готовая сборка показывает тот же экран.

## ЛР 2. Страницы приложения и навигация

Установлен React Router. Добавлены типизированный массив заданий (5 демонстрационных записей), повторно используемый компонент карточки `AssignmentCard`, страницы списка и подробностей, заглушка создания, страница «не найдено» и общий layout с навигацией. Подключены маршруты через `BrowserRouter`, `Routes` и `Route`. Запись определяется по параметру адреса `:id` через `useParams`.

### Как проверить

1. `npm run dev`, открыть `/` — виден список из пяти заданий.
2. Открыть две разные карточки, сравнить содержимое.
3. Скопировать адрес одной карточки, открыть в новой вкладке и обновить страницу — задание отображается корректно.
4. Перейти по ссылке «Создать» — видна заглушка и общая навигация.
5. Открыть `/unknown` — видна страница «не найдена».
6. Открыть `/assignments/missing` — видно сообщение об отсутствующей записи.
7. Временно очистить массив данных — проверить сообщение «Заданий пока нет», затем вернуть записи обратно.
8. Проверить клавиши «назад»/«вперёд», узкий экран (без горизонтальной прокрутки) и переходы по Tab/Enter.
9. `npm run build` и `npm run preview` — сборка проходит без ошибок, прямое открытие карточки работает в preview.


## ЛР 3. Формы и локальное состояние приложения

Общий список заданий поднят в состояние компонента App (useState), добавлены функции создания, изменения и удаления записи с неизменяемыми обновлениями массива (spread, map, filter). Создана переиспользуемая форма AssignmentForm для создания и редактирования с отдельным черновиком, обязательными полями, предметной проверкой (для статуса «Выполнено» требуется описание результата) и отменой без сохранения. Страница подробностей дополнена кнопкой удаления с подтверждением через window.confirm. На странице списка добавлен локальный фильтр по статусу со сбросом. В общий layout добавлено пояснение о временном хранении данных.

### Как проверить

1. `npm run dev`, создать новую запись с корректными данными — открывается её карточка, запись видна в списке.
2. Изменить несколько полей существующей записи через редактирование — карточка и список отражают изменения.
3. Внести изменения в форму редактирования и нажать «Отмена» — исходная запись не меняется.
4. Проверить пустое название, отсутствие срока и нарушение предметного правила (статус «Выполнено» без описания) — показывается ошибка, введённые данные не теряются.
5. Переключить фильтр по статусу, затем сбросить его — проверить отсутствие совпадений и возврат полного списка.
6. Отменить удаление в диалоге, затем подтвердить — запись удаляется, открытие её адреса показывает «Задание не найдено».
7. Удалить все записи — показывается пустой список, из него можно создать новую запись.
8. Перейти к редактированию разных записей по очереди — поля формы соответствуют выбранному id.
9. Обновить страницу (F5) — восстанавливаются пять демонстрационных записей; открытие нового (несуществующего в демо-наборе) id показывает «не найдено».
10. `npm run build` и `npm run preview` — сборка проходит без ошибок, создание/редактирование/отмена работают в готовой сборке.
